# 本地台灯遥控方案

## 目标和已确认决策

日期：2026-10-29。

用现有 ESP32-S3 和 CC1101 模块模拟原遥控器。手机、电脑与 ESP32 连接同一家庭 Wi-Fi，通过 ESP32 托管的网页控制；不做云服务和外网访问。

当前第一版只提供开关控制和状态校准：网页发送经过验证的切换命令，并通过推算状态判断目标开关动作。调亮、调暗、色温、模式和定时在后续阶段实现。保留原遥控器和灯身按键。

已知遥控器说明包含阅读模式；养眼模式标注为全光谱版，控轴模式标注为控轴版。必须确认用户实际灯款，不把说明书所有模式都默认视为可用。说明书还包含定时关闭、45 分钟定时休息，这些原厂命令与 ESP32 自己执行的定时分别建模。

## 当前实施优先级

“采集已配对遥控器的短按开关键 → 原样重放 → 台灯实际开/关”已完成首次实物验证。网页与 CC1101 已合并，当前只实现开关控制和状态校准；其他功能后做，不以破解加密为前提。

已确认同一固定样本可反复生效，开关键是**切换**而不是独立的开/关目标命令。因此网页和定时必须维护推算状态；没有回传时不能保证执行结果是开还是关。原遥控器模拟按键可作为备用路线，但当前射频重放已经可行。

## 硬件

| 部件 | 选择 | 用途 |
|---|---|---|
| 主控 | ESP32-S3-WROOM-1 N16R8 开发板 | 固件、网页、状态和定时 |
| 射频 | E07-M1101D-TH，CC1101，433 MHz 弹簧天线版 | 半双工接收和发射 |
| 辅材 | 合适的杜邦线、USB 数据线、稳定 USB 电源 | 连接、烧录、供电 |
| 原遥控器 | 已与灯配对的原装遥控器 | 学习、对照和日常备用 |
| 可选后续 | 带电池的 RTC | 无网络校时情况下断电重启后恢复准确时间 |

CC1101 单模块即可，不能同时收发。模块供电和 GPIO 都用 3.3V。

## 已知与待验证

- 原遥控器已确认使用 RF / R433；默认 433.92MHz OOK 异步配置已完成接收与重放实物验收。
- 有对码机制，但本次固定样本重放成功，说明当前开关命令没有阻止已验证样本重放的保护。
- 开关键已确认为切换命令；网页只能提供“翻转开关状态”，定时开关需要先解决状态可信度。
- 色温和亮度是否支持绝对值，需要分析协议；第一版不承诺百分比和 Kelvin 数值滑块。

## 开发架构

使用本机原生 ESP-IDF v6.1 + CMake + idf.py，不使用 Arduino 或 PlatformIO。所有运行依赖来自 ESP-IDF 自带组件。

| 模块 | 职责 |
|---|---|
| Radio | CC1101 原生 SPI 初始化、超时与寄存器校验；RMT DMA 接收和发射；频率配置 |
| Remote commands | 按键命令、短按/长按语义、原遥控器帧识别 |
| Lamp state | 根据已验证命令估算状态，并保留未知状态 |
| Scheduler | 倒计时、按星期任务、时间有效性、避免重复执行 |
| Storage | 已学习命令、网络配置、定时设置和版本迁移 |
| Web/API | 本地页面、按钮按住/松开、任务编辑和状态展示 |

当前合并固件覆盖 Radio、RMT DMA 波形重放、SPIFFS 样本存储、Wi-Fi、HTTP、Three.js 页面和 NVS 推算状态。网页不会发送未经验证的任意脉冲，只调用已经保存的 `power_sample_1`。

正式版本首次配置拟采用临时 Wi-Fi 配网入口，配置保存后加入家庭网络；提供局域网 IP，mDNS 名称作为便捷入口。不得要求用户把家庭 Wi-Fi 密码提交到代码仓库。

## 网页行为

- 当前控制页：状态校准、开灯、关灯和 3D 灯光预览。
- 后续控制页：调亮、调暗、色温切换、按住调色温、适用模式。
- 按住调节必须有最长发送时长；浏览器失焦、断开或缺失松开事件时停止，避免无限发射。
- 定时页：倒计时快捷值及自定义；每周任务的时间、星期、动作、启停、删除。
- 状态页：时间同步情况、网络、最近命令、推算灯状态。
- 发射完成不等于灯已执行。没有回传时，界面不显示伪造的设备确认。

## 状态与定时约束

已确认只有一个切换命令。当前网页要求先校准实际状态，再按目标决定是否发送一次切换；状态保存在 NVS。指定开关定时仍需要可信状态，没有回传时只能沿用同一套推算与校准约束。

平时监听原遥控器以更新状态，但可能漏收；灯身操作、设备断电、发射期间操作均可能造成状态未知。正式版本至少区分未知、推算开启、推算关闭。

时间使用中国标准时间 UTC+8。通过 NTP 联网校时；也提供手机校时入口。已校时且保持供电时，外网中断仍执行本地任务。断电重启且无有效时间时暂停每周任务并提示校时。

默认规则（后续开发据此实现）：

- 每周任务持久化；重启后过期任务不补执行。
- 倒计时使用单调时钟，不受 NTP 调时影响；重启后取消。
- 同一任务同一天到点只执行一次；跨分钟轮询不重复发射。
- 同一时刻冲突任务需要在保存时提示；射频命令串行排队。
- 原厂定时与 ESP32 定时可能叠加，网页要区分并说明。

## 开发里程碑与验收

1. **联通**：稳定读取 CC1101，接线正确，无上电自动发射。
2. **接收**：同一按键至少采集 5 次，比较实际脉冲结构；同时采集无按键基线。
3. **重放**：原遥控器不操作时，ESP32 单独发射可让灯响应；记录成功率与距离。
4. **按键**：逐个验证短按、长按和模式；避免把对码长按作为普通开关。
5. **协议结论**：确认开关语义、重复帧、设备身份、是否需要额外配对以及可支持的定时能力。
6. **网页**：合并固件已实现局域网开关控制和状态校准，待实物联动验收。
7. **定时**：验证正常执行、重启、无时间、校时、取消、冲突和设置持久化。

硬件验证失败时先停在射频阶段，留下采样，不提前开发会给用户错误承诺的网页控制。

## 当前交付与边界

已交付并合并原生 IDF 射频驱动、Three.js 网页、状态校准和开关控制。开关命令及 ESP32 重启后加载样本均完成实物验收；开发板已确认是 ESP32-S3-WROOM-1 N16R8，当前 GPIO 配置已用于成功收发。合并固件已编译和浏览器模拟测试，家庭 Wi-Fi 下的真实网页发送、多轮成功率、距离、其他按键仍待继续验证。
