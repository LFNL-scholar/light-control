# 接线与烧录（原生 ESP-IDF）

## 硬件前提

目标为 ESP32-S3，默认 Flash 布局为 4MB，无 PSRAM 依赖。4MB 及以上 Flash 的 S3 板可用这套布局，但必须核对实际板子 GPIO 占用。带屏、摄像头等板子可能占用参考 GPIO，不能直接照接。修改点是 `main/config.h`。

所有数字是 GPIO 编号，不是排针第几脚。先断电接线，CC1101 电源与逻辑都是 **3.3V**，不接 5V。

## 用户实际开发板（2026-10-30）

用户提供型号 ESP32-S3-WROOM-1，后缀 MCN16R8；按 N16R8 规格（16MB Flash、8MB PSRAM）记录。照片显示 ESP32S3 DevKitC 双 Type-C 板，当前 GPIO4、5、10、11、12、13 均在排针上，配置可沿用。PSRAM 相关 GPIO35～37 不用于本项目；板载 WS2812 丝印 GPIO48，也未占用。

**以正面元件朝上、天线朝上、Type-C 朝下为准：左侧标 USB，是默认脚本使用的原生 USB；右侧标 UART，是 USB 转串口。**推荐先插左侧，执行 `./flash.sh`。当前保留 4MB 布局即可运行，不需要为此开启 PSRAM 或修改 Flash 配置；未使用的容量不影响收发实验。模组后缀小字未从照片独立核清，容量以用户提供的 N16R8 为依据，首次连接可再读取芯片信息确认。

## 接线表

| CC1101 引脚号 | 名称 | ESP32-S3 参考连接 | 作用 |
|---|---|---|---|
| 1 | GND | GND | 共地 |
| 2 | VCC | 3V3 | 供电，不接 VBUS/VIN/5V |
| 3 | GDO0 | GPIO4 | RMT 发射数据输入到 CC1101 |
| 4 | CSN | GPIO10 | 软件片选，等待 CHIP_RDYn 后时钟传输 |
| 5 | SCK | GPIO12 | SPI 时钟 |
| 6 | MOSI | GPIO11 | ESP32 → CC1101 |
| 7 | MISO/GDO1 | GPIO13 | CC1101 → ESP32，SPI 读回 |
| 8 | GDO2 | GPIO5 | CC1101 接收脉冲 → RMT |

模块图虽然把 GDO0 标成输出，但在 CC1101 异步发射模式中，它用作调制数据输入；本固件接收期间配置该脚为高阻，接收输出走 GDO2。不要短接 GDO0、GDO2。

按你提供的模块图：**有芯片的正面朝向你，弹簧天线朝下**，顶部两排为：

```text
     7  5  3  1
     8  6  4  2

        芯片

        天线↓
```

从背面看会镜像，最终以到货丝印和厂家引脚图为准。9、10 号安装孔不接线。建议短杜邦线（约 10～15cm），确认排针和弹簧天线已焊接。初测遥控器距离模块 0.5～2m，避免过近过载和紧贴金属。

## 一键编译、烧录、打开串口

接开发板原生 USB Serial/JTAG 数据口，在项目目录运行：

```sh
./flash.sh
```

多个端口时：

```sh
./flash.sh /dev/cu.usbmodem你的设备
```

使用 USB 转 UART 口时：

```sh
LIGHT_CONSOLE=uart ./flash.sh /dev/cu.usbserial你的设备
```

UART 版使用 UART0 默认引脚（ESP32-S3 通常为 TX GPIO43、RX GPIO44），适用于开发板自带的 USB 转串口。若板子的串口桥接到其他 GPIO，需根据原理图修改 IDF 控制台配置。两个接口共用供电并不代表共用串口，按实际板子标注选择。

脚本自动加载你已有的 EIM / ESP-IDF v6.1 环境，调用原生 `idf.py flash monitor`；flash 会自动先完成必要的构建。未发现板子时会报串口连接错误，不会伪造烧录成功。

只编译分别使用：

```sh
./build.sh
LIGHT_CONSOLE=uart ./build.sh
```

退出 IDF 串口：**Ctrl+]**。串口波特率默认 115200。合并固件没有交互式命令提示符，日志会自动输出。

如果下载失败，确认数据线不是纯充电线，关闭其他占用串口的软件；必要时按住 BOOT、短按 RESET、松开 BOOT，再运行烧录。USB 串口可能重新枚举，必要时重新指定端口。还不能看到日志时按 RESET。

## 构建输出

- 原生 USB：`build/light_control.bin`、`build/bootloader/bootloader.bin`、`build/partition_table/partition-table.bin`。
- UART：对应 `build-uart/` 目录。
- 自动生成的 `flasher_args.json` 和 `flash_args` 包含烧录地址。应用 bin 不是整片镜像，正常使用 `./flash.sh`，不要把应用 bin 写到 0x0。
- 默认应用从 0x10000 开始，SPIFFS 存储从 0x190000 开始，布局见 `partitions.csv`。

首次挂载失败会格式化本项目 storage 分区。普通 flash 只写 bootloader、分区表、应用，不主动擦除 storage，但分区变化、整片擦除或挂载故障仍可能丢失槽位。通过 `dump` 在电脑保存重要样本。

从旧实验迁移后使用新的 SPIFFS 和带 CRC 的文件格式，不兼容旧 LittleFS 波形槽位。当前没有实际设备数据迁移需求。

## 启动检查

正常启动日志应包含 `Loaded 'power_sample_1'`、`HTTP server started`、`OPEN IN BROWSER: http://...` 和 `Web ready: http://...`。打开实际地址后，先按台灯现状校准，再测试开/关。

没有接 CC1101 或接错线时，CC1101 初始化会在有界超时后报错；网页仍可打开，但状态会显示射频未就绪。断电修正接线并重新上电。不要带电插拔。
