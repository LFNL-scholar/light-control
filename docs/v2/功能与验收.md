# v2：主题与用灯记录

## 约定

- 外观：右上角 36px SVG 太阳/月亮按钮，点击在手动浅色、手动深色与自动之间循环；自动时以小圆点标记。按钮提示当前与下一模式。默认自动，北京时间 08:00（含）至 18:00（不含）浅色，其余深色。手机浏览器的时钟决定当前时间；不依赖手机所在时区。手动选择一直保持，切回自动才恢复定时，每个浏览器独立保存。
- 统计来自网页控制与状态校准，属于推算数据，不代表真实状态回传。原遥控器或灯身触控不会被自动记录。
- 设备保存最近 12 个自然月的每日区间，按北京时间自然日清理过期日期。周一至周日为一周。跨午夜分摊到两天。清理只处理 `h<日期编号>.bin` 历史文件，不触碰射频样本。
- 日视图：24 小时时间轴、开灯时段/时长、网页开关与校准时间。周/月视图：每日时长柱状图、总时长、有效记录日均。点击柱子可进入日视图。
- 日均只纳入有有效开或关记录的日期；部分记录日也纳入，不补齐未知时间。只有关灯记录的一天是有效零时长；整天未知不算零。未来时段留空。
- 校准仅从当时起生效；此前推算时长保留，不推测真实开关发生时间。
- 关闭网页仍记录，多手机共享；定时刷新报表为 30 秒，操作完成后立即刷新。
- 每次重启都需要重新校准状态。此前记录保留，最后落盘端点之后至重新校准之前都是未知。每分钟保存一次进度，正常调度下断电前可能留下最多约 65 秒的未知尾段；文件系统损坏/写入失败会另外提示，不能承诺物理断电下零数据损失。
- SNTP 校时使用 `ntp.aliyun.com`，需要路由器能访问外网 UDP 123。未获得网络校时前仍能控制台灯，期间不记录时长；校时成功后只从当前开始，不回填之前的时段。校时后的短暂断网不停止本机计时。
- 系统时间发生明显跳变时在最后观察端点结束旧区间，从新时间重新记录。重叠的矛盾状态显示为未知，不重复计算。

## 实现与存储

`main/history.c` 封装区间日志、恢复、CRC 校验、过期清理与流式 JSON。每条记录 32 字节，每次状态变化与每天零点追加日志；活动区间在 NVS `lamp_history/active_v2` 保存检查点。复用原 SPIFFS 分区，未变更分区表、引脚或射频波形。恢复只关闭到已保存端点，绝不推算跨重启时长；重复恢复记录在写入/统计时去重。

正常一天 50 次状态变化时，全年原始区间约 600 KB，另有文件系统开销；具体容量受现存样本、操作频率与 SPIFFS GC 影响。空间不足或写入错误会停止新增统计并在网页提示，不删除保留期内数据腾空间。历史读取按最多 31 天分块流式输出，不将一年历史载入内存。

为保护射频样本和历史，挂载失败不再自动格式化 SPIFFS，NVS 空间/版本异常也不再自动擦除。已有设备的正常分区继续使用；存储异常需先诊断，不能通过整片擦除“修复”。

接口：

- `GET /api/state` 新增 `time_synced`、`history_ready`、`history_recording`、`history_error`。
- `GET /api/history?from=<UTC秒>&to=<UTC秒>`：起止须是北京时间零点，左闭右开，最多 31 天。响应含 `now`、`oldest`、`ready`、`time_synced`、`recording`、`error`、`incomplete`、`records`。
- `records` 每条为 `[开始UTC秒, 结束UTC秒, 开灯0或1, 来源]`，来源 0=跨日延续，1=网页控制，2=校准，3=时间同步或时间跳变后开始记录。零长度记录保留当时操作标记。
- 历史读取失败不会禁用灯光控制；损坏记录不纳入时长，并显示不完整提示。

## 烧录与实物验收

```sh
./flash.sh
```

使用左侧原生 USB，等待日志中的网页地址，手机连接同一局域网打开：

1. 等待 `Time synchronized` 日志；未校时提示应消失。按实物状态校准。
2. 开灯约 2 分钟后关灯，查看日时间轴/开关记录、周/月柱状图；第二台手机应读取同一历史。
3. 关闭网页，稍后再打开，设备持续通电时统计应继续。
4. 开灯至少 2 分钟后断电，等待一段时间重启；应提示待校准。确认历史保留，断电期间不累计，校准只从当前生效。
5. 断开外网后重启，但保持本地 Wi-Fi：网页与灯光控制可用，时间未同步期间不记录。恢复外网、成功校时后从当时开始记录。
6. 手机检查浅色/深色与自动；刷新后手动偏好仍保留。自动模式仅改变网页外观与 3D 场景，不改变灯的开关。

硬件烧录、真实断电恢复、外网校时、真实射频联动和手机 WebGL 性能均需实物验收。不会自动产生 v1 时期的历史。
