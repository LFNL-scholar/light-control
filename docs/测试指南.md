# 原生 ESP-IDF 射频测试指南

> 当前烧录入口 `./flash.sh` 已是网页与射频合并固件，启动后显示 Wi-Fi 日志和网页地址，不再提供下面的 `rf>` 交互命令。本文保留前一轮射频验收步骤，供以后重新学习其他按键时恢复或扩展测试工具；开关样本已经完成验收并保存为 `power_sample_1`。

## 开关优先验证流程

开关控制已完成首次验证：同一保存样本连续重放能够开灯、关灯，已确认是切换命令。接下来验证重启后加载、成功率、距离及其他按键。继续使用已经配对的原遥控器，**开关键只短按并立即松开**，长按用于对码，本轮不测试。

1. `status` 检查模块；先无按键运行 `capture 5000`、`dump`，保存基线。
2. 让灯处于肉眼确认的开启状态，输入 `capture 5000`，看到提示后短按开关键；记录灯是否关闭。`dump` 导出后用 `save power_from_on_1` 保存样本。若按键前采样就结束，可能只是噪声，不能当成功。
3. 再从关闭状态采集一次短按，记录实际结果，保存 `power_from_off_1`。两种起始状态各采至少 3 次，保留日志便于比较。
4. 加载一个完整样本，先肉眼记录灯当前状态，再单次 `play`；再次记录状态。每次只发送一次，不先用重复发送，也不自动对码。
5. 对同一个样本，分别从“已开”和“已关”两种状态单次重放。需要时用原遥控器或灯身按键恢复起始状态，并记录这一步。重复几轮、重启 ESP32 后加载再试，确认旧样本是否可重复生效。

| 同一个样本的实际效果 | 初步判断 |
|---|---|
| 开着时关，关着时开 | 倾向于切换命令，不能称为独立开/关 |
| 开着时关，关着时保持关 | 倾向于关灯目标命令，需更多样本验证 |
| 开着时保持开，关着时开 | 倾向于开灯目标命令，需更多样本验证 |
| 不响应或偶发响应 | 先排查噪声、完整性、频率、时序和重复帧，不能直接认定加密 |

`status` 显示的是 ESP32/CC1101 状态，不是灯的真实开关状态。本轮验收依据是灯实际响应。若旧样本稳定可重复控制，就先采用该路线，不必先理解每一位数据。若失败，拿多份 dump 分析，不盲目扩大重放次数或触发对码。

下文调亮示例保留为次级调试手段：如果开关键现象难以判断，可用调亮辅助验证射频链路，但不是当前的主要功能目标。

## 采样方式与旧版区别

本版用 **RMT DMA** 硬件采集和发射，时间分辨率为 1μs。CC1101 默认配置 433.92MHz OOK，带宽请求 325kHz、解调数据率请求 4.8kBaud、名义发射功率 0dBm。带宽和数据率量化到芯片支持值；这些参数仍需实物验证。

`capture 5000` 表示最多等待 5 秒，取第一个至少有 16 段脉冲的波形段，**不是录下 5 秒所有信号**。某个电平持续达到 `idle` 阈值（默认 20ms）时结束这一段；跨越该间隔的其他重复帧不会拼接。

没有解码或自动识别遥控器，噪声也可能很快满足条件。`valid=1` 只说明波形结构、时长、容量满足程序要求，不证明协议正确。先导出对照，再重放。

## 1. 检查与无按键基线

```text
status
capture 5000
dump
```

这次不按遥控器。可能超时，也可能录到噪声，保存串口日志作为基线。`radio=0` 时先查接线，不进入收发实验。

## 2. 采集真实按键

输入：

```text
capture 5000
```

看到 `Arming RX now` 后迅速短按一次**调亮**键，观察采样是否刚好在按键时结束。如果按键前就录完，优先怀疑噪声。不要一直按住。

采样完成后：

```text
dump
save bright_up_1
```

重复至少 5 次，分别保存 `bright_up_2` 等槽位，并把 dump 复制到电脑。比较与基线的差异、重复结构、少数固定脉宽及同一按键的一致性。`save` 会拒绝空、截断或结构无效的波形，但不能替你识别噪声。

### dump 格式

```text
RAW_BEGIN freq=433.92000 bw=325.0 rate=4.80
0,-1700
1,350
2,-1050
3,350
...
RAW_END
```

第一列是从 0 开始的段索引；第二列是带符号的微秒数：正为 HIGH、负为 LOW。这些数字仅说明格式，不是台灯编码，不能照例子发射。

硬件滤掉小于配置阈值的毛刺，默认 1μs；相邻同电平段会合并。RMT 检测静默后可能记录末尾静默片段或 EOF（零时长 EOF 不导出）。波形首尾、完整性仍需结合多次采样检查。

缓冲区最多 4096 个 RMT 符号／8192 段，最长合法波形 3 秒。缓冲区占满时保守判为可能截断，拒绝重放。采样等待最多 10 秒，到时取消 DMA，不使用半截数据。

## 3. 单次重放

确认录到规律的真实按键，并让灯处于能观察变化的亮度，再输入：

```text
play
```

只重放整个当前波形一次，不自动补帧。`TX finished; RX restored` 表示发送完成并恢复接收，**不代表台灯确认执行**，肉眼观察灯。

如果灯已经最亮，先用原遥控器调暗再测。如果单帧不能触发，但原遥控器明显发送重复帧，可以尝试：

```text
play 3 30
```

即整段波形发 3 次，中间 LOW 30ms。这是实验参数，不代表实际协议要求；开关切换命令重复可能切回原状态。应根据真实重复帧间隔调整。

验证成功后：

```text
save bright_up
reboot
load bright_up
play
```

这样检查断电/重启后持久化和重放。上电、加载都不会自动发射。

## 4. 裁剪与分段参数

如果波形前后混入噪声，可以查看 dump 后：

```text
trim 12 95
```

仅保留当前索引 12～95，包含两端，重新从 0 编号。索引只是例子，必须按实测选择；建议从命令首个 HIGH 开始并保留完整命令和必要间隔。裁剪只改内存，满意后用新槽位保存。

若 20ms 静默阈值把命令切断，可用 `idle 30000` 增至 30ms；若噪声不断让缓冲区满，可尝试适当减小阈值，但过小可能切断真实帧。大于 30ms 的帧间隔需要分开分析，此版不会无缝拼接所有帧。

`filter 0` 关闭硬件毛刺滤波，`filter 1` 恢复默认。ESP32-S3 默认 APB 80MHz 时硬件滤波寄存器只有 8 位，因此本工具只允许 0～3μs，不提供无效的几十微秒硬件滤波参数。

## 5. 按键扩展

依次验证调暗、色温切换、短按开关、阅读及实际灯款支持的模式。每个按键独立保存。

**开关键长按用于对码**，不可当作日常开关命令采集。长按色温需另采样，比较重复机制。原厂定时、45 分钟休息与 ESP32 将来自己的定时功能分别记录。

原遥控器只有一个开关按钮，必须确认是切换还是目标状态。找不到独立开关命令时不能直接承诺可靠的定时开灯/关灯。

## 6. 命令表

| 命令 | 含义 |
|---|---|
| `help` / `status` | 帮助／设备与波形状态 |
| `init` | 重置并重新配置 CC1101 |
| `reboot` | 重启 ESP32，不发射 |
| `capture 5000` | 最多等 5 秒，捕获第一个至少 16 段的波形段；允许 100～10000ms |
| `dump` | 导出当前波形，即使不是已识别协议 |
| `trim first last` | 裁剪，索引包含两端 |
| `play` / `play 3 30` | 发一次／发三次且中间 LOW 30ms |
| `save name` / `load name` / `list` | 保存、加载、列出槽位 |
| `freq 433.92` | 433.05～434.79MHz |
| `bw 325` | 接收带宽请求值 58～812kHz |
| `rate 4.8` | 解调数据率请求值 0.6～100kBaud |
| `idle 20000` | 接收分段阈值，1000～30000μs |
| `filter 1` | 毛刺阈值，0～3μs，0 禁用 |

槽位名称只用英文字母、数字、下划线、连字符，最长 24 字符。同名覆盖，存储使用 CRC32 检查文件完整性。保存时带上频率、带宽、数据率；load 会恢复这三项，校验失败会清空当前波形以防误发。

修改 freq/bw/rate 会让内存波形失效，需重新采集或加载槽位。idle/filter 影响下次采样，不改变已有波形，也不单独持久化。发射前会按波形自己的 RF 配置重新设置 CC1101。

## 7. 故障排查

| 现象 | 下一步 |
|---|---|
| 没串口输出 | 检查原生 USB 与 UART 选择、数据线、串口；RESET 后输入 status |
| radio=0 或 ESP_ERR_TIMEOUT | 断电检查 3.3V、共地、SPI、排针正反面；复位后 init |
| radio=1 但没规律信号 | 检查 GDO2→GPIO5、原遥控器电池和能否正常控制灯；改变距离 |
| 还没按键就采完 | 可能是噪声。与基线比较、改变位置、减小 bw；不要据此重放 |
| 无明显接收 | 优先向卖家确认精确频率；可分别试 freq 433.42 / 433.92、bw 650，每次重新采样 |
| 缓冲区满/ESP_ERR_INVALID_SIZE | 可能是持续噪声、过长或截断数据。减小 bw、调整 idle；不会发送截断波形 |
| 脉宽不稳定 | 分别试 rate 2.4 / 4.8 / 9.6；一次只改一项并记录 |
| 规律波形重放无效 | 查 GDO0→GPIO4、频率、完整帧、重复次数和间隔、原遥控器是否已配对 |
| 同一键多次不同 | 留多份采样，可能含状态、计数器或滚动码，不能直接判成加密 |
| ESP_ERR_INVALID_CRC | 槽位损坏或格式不兼容，重新采样；保留电脑日志 |

本工具没有 FSK 解码、频谱扫描或滚动码破解功能。OOK 仍无结果时，需要进一步资料、逻辑分析仪或 SDR 观察，而不是盲目重放。

## 8. 验收记录

使用 `实验记录.md` 记录按键、参数、距离、短按/长按、日志和重放成功率。只有实物重复验证过的命令才进入后续网页控制。编译通过、RMT 发完、SPI 状态正常都不能代替台灯实际响应。
